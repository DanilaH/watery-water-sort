# 0.46 — первый кадр без зелёной кнопки

Исходный HTML не содержал `gel-button` / `gel-primary`. В production CSS уже был
загружен, но оформление назначалось только после выполнения main-модуля с Phaser.
Поэтому до выполнения JS была видна прежняя зелёная кнопка; затем подключалась
SVG-оболочка. Загрузка/декодирование оболочки и шрифта добавляли ещё одну фазу.

## Изменение

- Все постоянные кнопки имеют окончательные классы в исходном HTML, включая
  золотые «Играть» / «Дальше». JS больше не меняет базовый вид этих элементов.
- Графика двух типов кнопок, золотой звезды, стекла меню и Rubik предзагружаются
  из `<head>`, параллельно загрузке JS. Всё находится внутри APK.
- Минимальный inline CSS и `inert` скрывают интерактивное содержимое до готовности
  контроллера, восстановления сохранённой темы и основных ресурсов меню.
  До этого виден только фон, без промежуточных кнопок и новых надписей загрузки.
- Ожидание ресурсов после инициализации ограничено двумя секундами, без обязательной
  задержки. Аудио, реклама и текстуры уровней в этот барьер не входят.
- При ошибке/зависании ресурсов доступны стабильные синие/золотые gradient-кнопки,
  текстовая звезда и системный шрифт. Позднее появление файла не меняет уже видимый
  запасной вариант. Пользователь не остаётся за невидимым inert-меню.
- Начальный фон Android WebView приведён к основному тёмно-синему фону игры.

Игровые правила, сохранения, рекламные тайминги и нативный фикс 0.45 не меняются.
Обновление preview3 поверх предыдущей версии, без очистки данных.

## Проверки

Новый `tests/browser/startup46.spec.ts` выполняется именно на production build через
`playwright.production.config.ts`: здесь CSS отделён от JS, как внутри APK.
Проверяются остановленный main-модуль, задержанная золотая оболочка, отсутствующие
оболочки/шрифт, ресурс, зависший дольше бюджета. После открытия меню работают его
кнопки, возврат из игры и настройки. Первый видимый нормальный экран уже содержит
окончательную графику и шрифт; при сбоях нет поздней смены запасной кнопки.

Новые четыре сценария вынесены из dev-набора, чтобы не дублировать их и проверять
нужный порядок загрузки. CI сохраняет все прежние 251 сценарий в трёх группах и
добавляет четыре production-проверки в первую группу. Итоговый `check` требует
успеха всех групп и Android-задачи.

Локально прошли 20 проверок меню/навигации/тем, затем все четыре production-сценария.
Итоговый CI и проверка APK будут записаны в `audits/clean-start-46/validation.json`.
Физический холодный запуск на телефоне в этом протоколе не заявляется.
