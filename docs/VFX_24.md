# Пробный набор сгенерированных VFX — 0.24

Запрос: сделать анимации богаче с помощью генерации, начать с брызг и победного фонтана и сравнить в движении.

## Ассеты и стиль

Built-in `image_gen`, прозрачный RGBA-атлас 1536×1024: глянцевые нейтрально-серые формы для окраски в игровые цвета. CLI/API fallback не использовался. Точный финальный промпт: [prompt.txt](audits/splash-24/prompt.txt).

| Файл | Форма | Размер |
|---|---|---|
| `public/art/vfx/splash-0.webp` | Вытянутая капля | 128×128 |
| `public/art/vfx/splash-1.webp` | Круглая капля с хвостом | 128×128 |
| `public/art/vfx/splash-2.webp` | Закрученная брызга | 128×128 |
| `public/art/vfx/splash-3.webp` | Трёхлопастный веер | 512×512 |
| `public/art/vfx/splash-4.webp` | Лента с капельками | 128×128 |
| `public/art/vfx/splash-5.webp` | Четырёхлучевой блик | 128×128 |

Все шесть итоговых ассетов сохранены в проекте. Общий вес lossless WebP — 133 912 байт. Крупный веер сохранён в повышенном разрешении для большой колбы; остальные формы не требуют такого размера. `sprites.json` сохраняет SHA исходного generated PNG, кропы и хеши файлов. `tools/build-vfx-24.py` выполняет только кроп, сохранение alpha и уменьшение с сохранением пропорций; формы не заменяются нарисованными вручную.

Исходная генерация имеет корректный alpha; дымка, видимая в чёрной подложке превью, не является непрозрачным фоном. Проверено композитингом на синем фоне. Кропы индивидуальные: первая капля немного вышла за условную границу строки, поэтому простая нарезка равных клеток дала бы обрезанный край.

## Поведение в игре

Нейтральные формы один раз окрашиваются во все восемь цветов через Canvas, с сохранением белых specular-бликов. Фонтан смешивает мелкие капли, несколько крупных закрученных брызг, краткий раскрывающийся веер у горлышка и редкие самостоятельные искры. Струя, порядок хлопков, траектории, усиление большой цели и перекрытие с буквами/звёздами сохранены.

Прототип заменяет оформление победного фонтана. Обычное переливание, волны, звук, вибрация и приём ходов не менялись. Оформление не распространялось на прочие эффекты до оценки пробного результата.

Canvas по-прежнему занимает весь экран, не перехватывает указатель и удаляется при завершении/навигации. В reduced motion остаётся спокойный старый акцент без текстурного фонтана. Поддержан fallback из простых капель, если набор спрайтов не настроен.

Плотность полноэкранного эффекта оставлена прежней: максимум 2×; плотность игрового поля/жидкости из 0.23 не меняется. В промежуточном варианте проверялся эффект 3×, но увеличение числа пикселей в 2,25 раза для всей поверхности экрана отклонено. Цветные Canvas-текстуры создаются один раз, а не на каждом кадре. Их верхняя оценка RGBA-памяти: около 10,5 MiB (восемь наборов с большим веером), без учёта GPU-копий/служебных данных браузера.

Дополнительно отдельный сценарий делает немедленный переход через MutationObserver: подтверждает запущенный сбор/ожидающие bursts и ноль arrivals до события, затем отсутствие всех arrivals и эффектов после.
