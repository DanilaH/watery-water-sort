# Поле и игровой интерфейс — 0.29

Второй из трёх согласованных пакетов. Первый — VESSELS_28.md, победа/награды — FINALE_30.md.

## Материалы и интерфейс

- Два generated gel-бэкинга (синий и золотой) и две звезды: crop + aspect-preserving downsample + exact lossless WebP, без текста внутри. Промпт/provenance в audits/ui-29/prompt.txt и public/art/ui/material-29.json. 307296 bytes исходных сжатых WebP, около 1.62 MiB общей декодированной RGBA-памяти. Транспортные SVG-контейнеры содержат ровно эти же WebP в image/data URI (без перерисовки/скриптов/внешних ссылок): GitHub binary blob API вернул Internal error даже для малого текстового blob, а CLI не имеет write-auth. Используется работающий text tree API, без изменения пикселей и build-системы. В ZIP base64 повторно сжимается.
- Live подписи/иконки/фокус и hit targets, CSS NineSlice для кнопок. Золото — основные действия/текущий уровень; синий материал — навигация. Plum/graphite/ice меняют тон только отдельного слоя материала, без фильтра на тексте/иконках. Настройки и level sheet получили тональные игровые поверхности, контрастные switch/selection состояния и цельные звёзды.
- Главное меню: вместо прежней SVG-иллюстрации собирается PNG на offscreen Canvas из того же стекла, геометрии и палитры, что в игре. В DOM остаётся ровно один игровой canvas. Нет постоянного цикла анимации меню. Старый SVG сохраняется как fallback при отказе decode. Rubik/формулировки/прогресс сохранены; техническая заметка о тестовом наборе убрана из выбора уровней.
- Пульсирует только skin «Дальше», кнопка и её область нажатия неподвижны. Проверка idle/click теперь также подтверждает стабильность прямоугольника кнопки.

## Поле

Ширина обычных колб увеличена примерно на 15–19% по доступной раскладке, высота — до 15% там, где хватает места. Ограничения короткого экрана важнее фиксированного процента. Максимум 62×250 вместо 54×218; pitch ratio .61 вместо .53, высотный предел ширины .34 вместо .285. Минимум касания 48 px и отдельный rewarded slot сохранены. Большая цель по-прежнему охватывает два ряда.

В высоком портрете HUD/nav компактнее, а высота feedback одинакова до и после победы: поле не скачет и не прерывает эффекты из-за ResizeObserver.
