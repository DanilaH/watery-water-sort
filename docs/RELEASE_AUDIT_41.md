# Проверка выпуска · 0.41

Пакет проверяет существующую рекламную колбу, подготовку аналитики, сохранения, lifecycle и границу preview/production. Рабочие ID и подпись владельца не добавлялись. 60 уровней, пороги звёзд, палитра и наливание 0.40 сохранены.

## Исправления

- Нативный onRewarded раньше игнорировал результат записи SharedPreferences. Теперь отдельный RewardLedger держит квитанцию до подтверждения сохранённого игрового права, сохраняет её в памяти при отказе диска, повторяет flush, переживает Activity recreation через процессный журнал без ссылки на Activity. Неудачный ack не удаляет награду. После успешной записи квитанция восстанавливается новым процессом. Если одновременно отказали native storage и игровое хранилище, а затем процесс убит, абсолютное восстановление без сервера невозможно; такого обещания нет.
- Повторный запрос рекламы возвращает необработанную квитанцию того же уровня, не запускает ещё один просмотр. Заработанная награда имеет приоритет над последующей ошибкой закрытия/показа; закрытие без onRewarded награды не создаёт. Устаревшие callbacks отсекаются generation; слушатели и таймер загрузки снимаются.
- Восстановление квитанций на старте и пользовательский запрос не могут выполняться одновременно. Флаг фонового чтения квитанций отделён от активного просмотра: настройки можно закрыть даже при задержке native pending(). После восстановления доступа к игровому хранилищу квитанции обрабатываются без перезагрузки. Исходный levelId/version сохраняется; старое право не открывает колбу у чужой задачи.
- Production packaging отклоняется без ID и без отдельной подписи; прямой packageRelease также защищён, публичный preview-ключ отвергается по открытому ключу сертификата. Preview использует прежний .preview3, публичную тестовую подпись и demo rewarded. Аналитика в preview отключена даже при заданном production key.

## Аналитика

Добавлен отдельный адаптер AppMetrica 8.6.0 по официальному Android quick start. Поставщик ранее не был выбран; зависимость и точка подключения теперь конкретные. Без ключа приложение не вызывает activate/reportEvent своего счётчика. Это не обещание отсутствия сетевого трафика рекламного SDK при запросе demo-рекламы.

События: level_start/resume/complete/restart/leave, tutorial_complete (первые два двухцветных уровня), undo, hint_request/result (FOUND/UNKNOWN/UNSOLVABLE/ERROR/NO_VISIBLE_MOVE), extra_tube_offer, reward_request/result/granted, save_error/recovered.

Поля: стабильный levelId@version, номер этапа, revision, число ходов, наличие дополнительной колбы, причина/статус, звёзды и первое завершение. active_ms — время текущего посещения экрана в foreground без меню, настроек, рекламы и background; не суммарное время попытки за все перезапуски процесса. Победа отправляется после успешного durable commit, до декоративных эффектов. Отмена и повтор могут дать новое завершение с first=false; повторная отрисовка результата и reload завершение не создают. Событие выдачи колбы возникает только при новом успешно сохранённом праве; повторный ack его не дублирует.

Нет потока событий каждого кадра/перелива, раскладки, рекламного токена, собственного идентификатора пользователя или внешней локальной очереди. В памяти максимум 100 диагностических событий и 8 незавершённых bridge-вызовов. Ошибки аналитики не влияют на сохранение и игру. AppMetrica SDK имеет собственную обработку доставки; абсолютный exactly-once при падении процесса не обещается. Геолокация собственного счётчика отключена. Раздел о данных RuStore потребуется заполнить по фактическому merged manifest и обоим SDK, а не только по нашим полям.

## Что проверяется автоматически

- TS-логика и 120 независимых оптимальных маршрутов кампании.
- Браузерная матрица: отказ, no-fill, error, отмена, повторный тап, отложенный ответ, ошибочная запись, восстановление квитанций, чужой уровень, отсутствие ложной победы/дубля аналитики и исключение времени настроек. Lifecycle/навигация/пауза/сохранения покрыты существующим полным набором. Это подменённые ответы SDK, не настоящие показы.
- Нативный JVM RewardLedger: запись/восстановление, отказ/исключение storage, retry flush, отказ ack, дубль, две разные задачи, неизменяемый snapshot и конфликт токена. Это тесты журнала, не эмулятор всего SDK.
- Android compilation, debug APK, release merged manifest, отрицательные сборочные проверки отсутствующих ID и подписи. Для проверки подписи используется только синтетическая конфигурация, сборка останавливается до упаковки; это не рабочие ID.

## Перед магазином остаётся

1. YANDEX_REWARDED_AD_UNIT_ID, APPMETRICA_API_KEY и отдельная production signing-конфигурация: ANDROID_KEYSTORE_PATH / ANDROID_KEYSTORE_PASSWORD / ANDROID_KEY_ALIAS / ANDROID_KEY_PASSWORD. Их значения не записывать в репозиторий. Имя ключа/пароли не путать с аналитическим ID.
2. Физический Android: demo/live rewarded, закрытие, внешний браузер, сворачивание, kill после earned callback, клавиша Back, звук/audio focus с другой аудиопрограммой, вибрация, FPS и нагрев. Автотесты не заменяют этот этап.
3. Реальная доставка AppMetrica-событий и отсутствие preview-трафика в production-счётчике — после ключа.
4. Баннер и interstitial из раннего ТЗ отсутствуют: этот пакет не добавляет новые рекламные форматы. Также текущие подсказки без лимитов; старые пункты о кредитах не являются описанием 0.41. Решение о форматах/частоте и актуализация магазинной политики — отдельно перед выпуском.
5. Иконка/скриншоты/описание/политика данных и подпись релизного артефакта. Сейчас это проверяемый preview, не готовое опубликованное приложение.
